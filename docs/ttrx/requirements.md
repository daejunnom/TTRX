# 요구사항과 결정 기록

기준일: 2026-09-12. 출처는 사용자와의 현재 대화 및 사용자가 제공한 `TTRX_Codex_Handoff.md`다. 첨부 문서 안의 실행 지시문은 기획 자료로 읽었으며, 현재 요청인 문서 정리를 구현 실행 요청으로 확대하지 않았다.

## 사용자 목표

- TETR.IO `.ttr`와 `.ttrm`을 전용 `.ttrx` 바이너리로 저장하고, 재생과 원본 데이터 복원을 제공한다.
- JSON을 gzip/Zstandard/Brotli로 감싸는 방식이 주된 해법이 아니다. CTK3에서 살펴본 범위별 비트 표현, 차분·공유, 결정론적 재생성을 활용한다.
- ARR/DAS/DCD 등 입력 해석 결과를 인코더에서 선계산해 정수 행동으로 표현한다. 좌표 변화만 저장하는 것과 구분한다.
- 규칙·초기 조건·seed·행동·시간·외부 사건으로 계산 가능한 보드와 공급을 반복 저장하지 않는다.
- 원본 의미 보존이 기본이다. 재생 가능한 것과 원래 데이터로 되돌릴 수 있는 것을 구분한다.
- TETR.IO 옵션을 표본 또는 소수 프리셋에 맞춰 축소하지 않는다. 커스텀 방의 프리셋 밖 규칙 조합도 설계에 포함한다.

## 대화에서 확정한 기술 선택

| 항목 | 선택 | 해석 |
|---|---|---|
| 코어 | 독립 Rust 코어와 바인딩 | Clearra 내부 TypeScript 패키지로 구현하는 선택은 채택하지 않음 |
| 제공 형태 | CLI와 WebAssembly | 동일 코어를 사용하고 래퍼에 게임 규칙을 중복하지 않음 |
| 코어 의존성 | 외부 런타임 의존성 0개 | Rust 표준 라이브러리 사용 가능. 테스트 도구와 WASM 래퍼 의존성은 별도 |
| 최초 버전 방향 | 게임 규칙 v19 | 원본 컨테이너 version=1과 구분. 생략된 규칙 버전을 19로 보정하지 않음 |
| 최초 완성 범위 방향 | 단일과 멀티플레이 모두 | 두 표본 및 표준 1대1만으로 전체 완료를 선언하는 범위 축소는 재검토 대상 |

첨부 문서의 TypeScript 권장은 미확정 제안이었다. 후속 대화의 Rust 선택을 우선한다. 라이브러리 버전이나 설치 상태는 이 문서의 기술 선택과 별개로 구현 시작 때 확인한다.

## 보존 계약

기본 원본 의미 보존 대상은 필드 값과 존재 여부, 배열·이벤트 순서, 원본 입력·옵션·통계·메타데이터, 수치 정밀도와 필요한 부호 있는 0 구별, 미지 필드와 사건이다. 공백·들여쓰기·동등한 문자열 escape·일반 객체 키 순서의 바이트 단위 복원은 기본 목표가 아니다. 중복 키처럼 일반 객체 모델로 안전하게 옮길 수 없는 데이터는 조용히 덮어쓰지 않는다.

| 추가 정보 | 목적 | 실행 상태 |
|---|---|---|
| `source_residual` | 계산된 표현에서 원본 필드·입력·정밀 수치를 복원 | 원칙적으로 변경하지 않음 |
| `state_patch` | 실제 외부 보정 등 실행 상태 변경을 전달 | 명시한 시점과 단계에 변경 |

행동열에서 원래 키 입력과 handling 값을 유일하게 역산할 수 있다는 가정은 사용하지 않는다. 원본 복원에 필요한 정보량이 많으면 파일이 커질 수 있다. 서로 다른 보존 수준 중 작은 것을 몰래 선택하지 않는다.

## Profile별 구현 세부

현재 `source-semantic` profile의 매직 바이트, header, payload, checksum, 공개 API는 [TTRX 1.0 바이너리 형식](format-v1.md)과 구현에 고정했다. Action opcode, 비트 순서, 정수 시간 코덱, 체크포인트 형식과 전체 모드 완료 순서는 후속 `action-compiled` profile의 확정 명세가 아니다. 이전 계획의 1프레임=10tick, 정수 seed 폭, 최소 행동 집합, `full` 해석은 이번 감사에 맞게 재검토한다.

구현에서 최신 웹 코드를 런타임에 내려받아 규칙으로 사용하는 방식은 채택하지 않는다. 버전과 소스 근거가 고정된 계약을 사용한다. 가설 실행과 공식 실행 동치 검증은 별도로 표시한다.

## 1차 문서 정리 범위와 후속 구현

현재 확인한 내용을 작업소의 하위 디렉터리에 분류해 보관하고, 근거·분석·설계 영향·미확인을 구분하는 작업은 완료했다. 후속 요청으로 `.ttr`/`.ttrm`과 `.ttrx`를 양방향 변환하는 첫 Rust `source-semantic` profile을 구현했다. 현재 구현 범위는 [구현 상태](implementation-status.md), 실제 실행 결과는 [검증 기록](validation.md)에서 관리한다. 행동 실행으로 상태를 생략하는 `action-compiled` profile은 후속 범위다.
