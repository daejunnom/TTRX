# 분석 결과가 TTRX 구현 설계에 미치는 영향

기준일: 2026-09-12. 이 문서는 현재 분석으로 수정해야 하는 설계 가정과 책임을 기록한다. 최종 API·opcode·바이너리 명세나 구현 완료 보고서가 아니다. [사용자 요구와 선택](requirements.md)을 유지한다.

## 기존 계획에서 수정할 가정

| 기존의 좁은 가정 | 반영할 근거 |
|---|---|
| Blitz와 표준 1대1 표본이 기본 완료 범위 | 기본 옵션 173개, 자유 커스텀 규칙, 모드·동적 상수·외부 사건 |
| 프리셋 이름으로 실행 규칙 식별 | 개별 설정, 프리셋 수정, room.constants, 경기 중 변경 |
| 초기 options 객체면 규칙 완성 | 상수 먼저 적용, handling/Zen 외부값, 서버 추가 설정 |
| seed는 고정 폭 정수이고 공급은 seed만의 함수 | fractional seed 허용 경로, 두 RNG, bag 내부 상태·Zenith 의존 |
| 1프레임을 10개의 같은 물리 tick으로 진행 | 호출별 safelock/SDF, 이벤트 경계, 프레임 단계·역순 예약 |
| 성공한 이동·회전·hold만 행동으로 남김 | 실패 입력·버퍼·held 효과·통계·모드 조건 |
| 7종 4셀 미노·10×20·SRS+ | 13개 기본 미노, 8개 킥셋, 임의 크기·custom 미노·상수 |
| renderer 코드는 모두 제거 가능 | 줄 삭제 연출의 공유 rngex 소비, pro_retry 종료 |
| full은 완전 checkpoint 또는 state_patch | 일부 snapshot이며 RNG·대기 큐·상수 등이 없음 |
| 기존 binary 구조를 lossless 원본 모델로 사용 | stats 기본값 복원·미지 필드·custom 미노 속성 손실 |

## 유지할 책임 경계

| 계층 | 책임 |
|---|---|
| 원본 어댑터 | 구조 인식, 필드·값·존재·순서·수치 정밀도 보존, 구버전 변환의 원본 정보 유지 |
| 계약 해석 | 컨테이너 버전·규칙 버전·소스 해시·상수·effective 초기값·실행 문맥 식별 |
| 원본 실행·추적 | 지원 계약의 raw 입력과 외부 사건을 실행하고 행동·호출 단계·상태를 관측 |
| 행동 컴파일러 | ARR/DAS/DCD 및 버퍼 실행 선계산, 의미 있는 시도·held 효과와 시간 순서 표현 |
| 결정론적 런타임 | 물리·공급·두 RNG·큐·공격·actors·모드·외부 변경을 고정 규칙으로 실행 |
| 바이너리 코덱 | 길이·참조·비트·정밀 값·공유·차분, 동일 보존 수준에서 비용 선택 |
| 원본 복원기 | 실행 결과와 source_residual로 원본 계열의 데이터 복원 |
| 검증·도구 | 원본 왕복·실행 동치·형식 안전·자원·성능 결과를 구분 |

코어는 독립 Rust, CLI와 WASM은 얇은 경계로 유지한다. 테스트 도구와 래퍼의 의존성을 코어 런타임 의존성 0개 조건과 혼동하지 않는다. 의존성 제거를 이유로 JS 수치 의미나 정확한 원본 수치를 근사하지 않는다.

## 상태와 데이터 계약에 필요한 추가 범위

raw/effective/mutable options와 derived state, constants의 출처·변경, bag/bagex/bagid/lastGenerated, RNG 둘, 현재 미노·skip·보드 셀 의미, 입력 효과·통계, 예약 큐, pending/continuous/ACK, targets/enemies, 레벨·stock·actors·Zenith 상태가 필요하다.

이 목록은 저장 시 모두 반복 기록하라는 뜻이 아니다. 이후 재생성 가능한 상태는 규칙 실행으로 계산하고, 초기 재개 상태·실제 외부 입력·원본 복원에 필요한 정보만 적절한 계층에서 표현한다. 최소 상태를 줄일 때마다 제거한 정보가 더는 후속 실행에 필요하지 않음을 검증한다.

동적 custom 사건에는 초기화와 다른 전이를 정의해야 한다. 기본값 불변 공유와 시간에 따라 변하는 옵션을 같은 최적화로 처리하지 않는다. 프리셋 이름은 사전 압축 힌트가 될 수 있어도 현재 이름표만으로 원본 실제값을 대체하지 않는다.

## 구현 전에 고정할 계약

정수 행동의 의미·입력 통계 및 held 효과 전달, event partition과 프레임 단계, JS의 반올림·나머지·pow/log1p 수치 의미, 외부 상수·설정 누락 처리, checkpoint 충분성, custom 데이터의 형식·자원 한도를 구체화해야 한다. 이전 계획의 checksum/비트순서/고정 시간 단위는 채택 완료로 기록하지 않는다.

기본 source semantic 보존과 결정론적 재생 가능 여부는 별도로 보고한다. 미확인 계약은 가설/미확인 상태로 드러내며, 원본 보존 성공만으로 실행 성공을 표시하지 않는다.

## 단계 구성에 적용할 원칙

작은 수직 구현으로 파서→추적→컴파일→실행→복원을 연결하되 그것을 전체 범위 완료로 바꾸지 않는다. 기능 목록 전체를 유지하고, [커스텀 방](../tetrio/options/custom-rooms.md)과 [검증 범위](../tetrio/verification/coverage-and-open-items.md)의 항목별 상태를 갱신한다. 첫 두 표본은 회귀 기반이고 프리셋·서버 설정·미노·모드 전체를 대신하는 acceptance 기준이 아니다.
